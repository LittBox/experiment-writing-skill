# Word 排版规范（强制）

本文件是 DOCX 生成与校验的唯一依据。`scripts/docx_styles.py` 按本文件生成样式，`scripts/validate_docx.py` 按本文件检查。以下全部为**强制要求**，不是建议。

## 1. 页面

| 项目         | 值                                            | 来源     |
| ------------ | --------------------------------------------- | -------- |
| 纸张         | A4，11906 × 16838 twips                      | 参考模板 |
| 页边距       | 上下 1440、左右 1800 twips（2.54cm / 3.17cm） | 参考模板 |
| 页眉页脚距离 | 851 / 992 twips                               | 参考模板 |
| 版心宽度     | 8306 twips（约 14.65cm）                      | 计算     |

## 2. 字体（强制）

### 2.1 允许使用的字体

| 用途                       | 中文（eastAsia） | 西文（ascii / hAnsi / cs） |
| -------------------------- | ---------------- | -------------------------- |
| 正文、表格内容、图题、表题 | 宋体             | Times New Roman            |
| 各级标题、表头             | 黑体             | Times New Roman            |
| 代码块                     | 宋体             | Courier New                |

字体白名单：`宋体`、`黑体`、`Times New Roman`、`Courier New`。不在白名单内的字体一律视为违规。

### 2.2 禁止项

- 禁止楷体（`楷体`、`KaiTi`、`Kaiti`、`STKaiti`、`楷体_GB2312`）。
- 禁止微软雅黑（`微软雅黑`、`Microsoft YaHei`、`YaHei`）。
- 禁止主题字体：不得出现 `asciiTheme`、`hAnsiTheme`、`eastAsiaTheme`、`cstheme`，也不得让 `w:theme` 提供默认字体。
- 禁止依赖默认字体：每个样式、每个 run 都必须明确写出 `ascii`、`hAnsi`、`eastAsia`、`cs` 四个属性。
- 禁止使用 macOS 专有字体名（如 `Songti SC`、`Menlo`），否则 Windows 上会被 Word 替换。

### 2.3 必须真正生效

- 文档默认值（`docDefaults`）、`Normal` 样式、所有自定义样式、所有 run 的 `rFonts` 都明确指定。
- 不能只改字体名称来通过检测：生成后要用 LibreOffice 转 PDF，检查实际嵌入或使用的字体（见测试方案）。
- `w:hint` 设为 `eastAsia`，保证中文标点按中文字体渲染。

## 3. 正文

| 项目     | 值           | Word 实际数值                                                 |
| -------- | ------------ | ------------------------------------------------------------- |
| 字号     | 小四 12pt    | `sz=24`、`szCs=24`                                        |
| 行距     | 1.25 倍      | `w:line="300" w:lineRule="auto"`                            |
| 段前     | 0.5 行 = 6pt | `w:before="120"`（twips）；同时去掉 `beforeLines`         |
| 段后     | 0.5 行 = 6pt | `w:after="120"`（twips）；同时去掉 `afterLines`           |
| 首行缩进 | 2 字符       | `w:firstLineChars="200"`，并写 `w:firstLine="480"` 作兜底 |
| 对齐     | 两端对齐     | `w:jc="both"`                                               |
| 颜色     | 黑色         | `000000`                                                    |

**0.5 行折算说明：** Word 的"行"单位随字号变化。本规范以 12pt 正文为基准，1 行 = 12pt，所以 0.5 行暂按 6pt（120 twips）实现。如果改变正文字号，需要同步修改此处。

正文段落保持统一的字体、字号、行距、段落间距，不允许在段落上做局部覆盖。

## 4. 标题

| 级别 | 字体 | 字号      | 其他               |
| ---- | ---- | --------- | ------------------ |
| 一级 | 黑体 | 三号 16pt | 加粗，居左，无缩进 |
| 二级 | 黑体 | 四号 14pt | 加粗，居左，无缩进 |
| 三级 | 黑体 | 小四 12pt | 加粗，居左，无缩进 |

- 颜色一律黑色 `000000`，不得使用蓝色或主题色。
- 首行缩进和左缩进均为 0（`firstLineChars=0`、`firstLine=0`、`left=0`）。
- 标题段前 12pt、段后 6pt，行距 1.25 倍，与下一段保持连带（`keepNext`）。
- 字号为草案，如需调整以你的确认为准。

## 5. 独立段落样式

下列样式互相独立，不得基于正文样式（`BodyText`）继承首行缩进。

| 样式 ID           | 用途         | 缩进        | 对齐           | 字体              | 行距                 | 段前后    |
| ----------------- | ------------ | ----------- | -------------- | ----------------- | -------------------- | --------- |
| `LabBody`       | 正文         | 首行 2 字符 | 两端对齐       | 宋体 / TNR 12pt   | 1.25                 | 6pt / 6pt |
| `LabHeading1~3` | 标题         | 无          | 左             | 黑体              | 1.25                 | 见上      |
| `LabTableText`  | 表格内文字   | 无          | 左（表头居中） | 宋体 / TNR 12pt   | 单倍                 | 0 / 0     |
| `LabTableHead`  | 表头         | 无          | 居中           | 黑体 12pt         | 单倍                 | 0 / 0     |
| `LabCaption`    | 图题、表题   | 无          | 居中           | 宋体 / TNR 10.5pt | 单倍                 | 见第 7 节 |
| `LabCode`       | 代码块内文字 | 无          | 左             | Courier New 9pt   | 固定 18pt（atLeast） | 0 / 0     |
| `LabCodeNum`    | 代码行号     | 无          | 居中           | Courier New 9pt   | 固定 12pt（atLeast） | 0 / 0     |
| `LabFigure`     | 含图片的段落 | 无          | 居中           | 同正文            | 单倍                 | 见第 7 节 |

> 参考模板中代码列段落带有 `firstLineChars=200`，这是模板的瑕疵，本规范明确**去掉**。

## 6. 表格

### 6.1 表格一：非数据类（配置、环境、说明）

| 项目       | 值                                                                 |
| ---------- | ------------------------------------------------------------------ |
| 边框       | 全框线，单线 `sz=4`（0.5pt），自动色                             |
| 表头底色   | `D7D7D7`                                                         |
| 表头字体   | 黑体 12pt，加粗，居中                                              |
| 内容字体   | 宋体 / TNR 12pt                                                    |
| 单元格边距 | 上下左右各 80 twips                                                |
| 对齐       | 表格居中，单元格垂直居中                                           |
| 定位       | 嵌入式表格，**不使用** `tblpPr` 浮动定位                   |
| 宽度       | 不超过版心 8306 twips；模板为 9186，超出版心，实现时按版心比例缩放 |

### 6.2 表格二：数据类（三线表）

| 项目       | 值                                                                                                       |
| ---------- | -------------------------------------------------------------------------------------------------------- |
| 边框       | 无竖线、无内部横线；表头上边线 3pt（`sz=24`）、表头下边线 1pt（`sz=8`）、表尾下边线 3pt（`sz=24`） |
| 表头底色   | 白色 `FFFFFF`                                                                                          |
| 表头字体   | 黑体 12pt，不加粗，纯黑                                                                                  |
| 单元格边距 | 表头上下 150、左右 240 twips；内容行上下 60、左右 240 twips                                              |
| 表头行     | 最小高 909 twips，跨页重复（`tblHeader`）                                                              |
| 宽度       | 不超过 8306 twips，自动或按比例                                                                          |

> 参考模板中表尾线和内容行格式未能完整读取，本规范的表尾 3pt 线与内容行边距是按三线表通用写法补全的，待你核对。

### 6.3 通用要求

- 表内段落使用 `LabTableText` 或 `LabTableHead`，无首行缩进。
- 所有表格都不得使用蓝色边框、蓝色底色或主题表格样式；不引用 python-docx 默认的 `Table Grid` 以外的带色样式。
- 行不允许被分页切断（`cantSplit`）。

## 7. 间距规则

| 对象           | 规则                                                                                                                                            |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| 表格与前后正文 | 上下各 0.5 行，按 6pt（120 twips）实现                                                                                                          |
| 图片与前后正文 | 上下各 0.5 行，按 6pt（120 twips）实现                                                                                                          |
| 表题           | 位于表格上方；段前 6pt，段后 3pt（60 twips），与表格贴近但不挤压                                                                                |
| 图题           | 位于图片下方；段前 3pt（60 twips），段后 6pt                                                                                                    |
| 实现方式       | 表格没有段前段后属性，用前一个段落的段后或一个 6pt 行高的空段落（`LabSpacer`）实现；优先调整相邻段落的 `before/after`，避免出现无意义空段落 |

## 8. 图题与表题

- 格式：`图1 说明文字`、`表1 说明文字`，全文连续编号（已由用户确认，不使用章号-序号）。
- 表题位于表格上方，图题位于图片下方，均为宋体五号（10.5pt）、居中。
- 编号由脚本维护，防止错号、漏号。
- 图题和表题不得为空，不得超过一行（超过时需要缩短）。

## 9. 代码块

- 结构：两列表格（行号列 709 twips + 代码列 7587 twips，合计 8296 = 版心）。
- 行号列：底色 `E7E5DC`，Word 自动编号 `decimalZero`（`01.`），每个代码块重新从 01 开始。
- 代码列：Courier New 9pt，行距 18pt（atLeast），隔行底色 `F8F8F8`。
- 无外框、无横线，只保留列间竖线；竖线颜色是否沿用模板的绿色 `65E266` 待你确认，默认改为灰色 `A6A6A6`。
- 语法着色沿用 GitHub 风格配色（模板色值）；关闭着色时全部为黑色。
- 代码中的中文注释使用宋体。
- 制表符展开为 4 个空格；超长行允许自动换行；不允许缩进被吞掉（使用 `xml:space="preserve"`）。

## 9.1 代码块字体检查例外

代码块的 `eastAsia` 为宋体、西文为 Courier New，仍然落在白名单内，不需要单独豁免。

## 10. 字体扫描规则（`validate_docx.py`）

### 10.1 扫描范围

| 范围                                             | 文件                                                                       |
| ------------------------------------------------ | -------------------------------------------------------------------------- |
| 正文段落、标题、表格全部单元格、图题表题、代码块 | `word/document.xml`                                                      |
| 页眉、页脚                                       | `word/header*.xml`、`word/footer*.xml`                                 |
| 样式及继承                                       | `word/styles.xml`（含 `docDefaults`、`latentStyles` 之外的所有样式） |
| 编号                                             | `word/numbering.xml`                                                     |
| 主题                                             | `word/theme/theme1.xml` 中被引用的字体                                   |
| 字体表                                           | `word/fontTable.xml` 中出现的字体                                        |

### 10.2 扫描项

对每一个 `w:rFonts`，读取 `ascii`、`hAnsi`、`eastAsia`、`cs` 以及 `asciiTheme`、`hAnsiTheme`、`eastAsiaTheme`、`cstheme`：

1. 出现楷体、微软雅黑，报错。
2. 出现任何 `*Theme` 属性，报错。
3. 字体名不在白名单，报错。
4. 对每个 run 沿"run → 段落样式 → 基础样式 → docDefaults"解析最终字体；任一属性解析不到，报"未明确指定"。
5. `fontTable.xml` 中存在楷体、微软雅黑，报警告。

### 10.3 报告格式

每条错误包含：文件路径、位置（段落序号或样式 ID）、违规属性、违规值、文字片段。末尾给出汇总数，发现任意错误时退出码为 1。
